# Asset storage and handoff

Keep reusable code and private production data separate. A job workspace holds inputs,
checkpoints, settings, renders, bakes and reports. The public source tree contains tools,
synthetic tests, generic recipes and documentation only.

Plan space for temporary copies as well as final outputs. Check checkpoint, cache, preview,
export, share and Library destinations independently. Make a verified copy before reclaiming
space, and delete only within the user's explicit scope.

Maintain accepted editable sources independently of optimized runtime derivatives. On delivery,
pin exact model/map/manifest bytes and declare formats, units, UV/source order and dependencies.
Hash downloaded or served bytes when claiming delivery identity; a database hash or re-saved
checkpoint is a different check. Re-import the actual export for visual and structural review.

Use supported Library APIs to attach source lineage and set durable retention. Upload success,
promotion, collection assignment and runtime adoption are separate states. An upload-size
failure should lead to the documented lossless route or a revised delivery plan, not silent
asset degradation or deletion of originals.

Record current job IDs, source paths, output hashes, views and measured results privately.
Public guides describe which checks to perform without publishing those records.
