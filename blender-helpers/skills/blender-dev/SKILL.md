# Blender developer

The asset-developer maintains capability; the asset-operator makes model decisions and accepts
real assets. Work on synthetic fixtures or an authorized private copy, never on an active job.

| Task | Skill |
|---|---|
| Classify/reproduce a request and return an actionable handoff | [Triage](../blender-dev-triage/SKILL.md) |
| Implement, test and document a tool change | [Release](../blender-dev-release/SKILL.md) |
| Plan checkpoint storage, uploads and verified archives | [Storage](../blender-dev-storage/SKILL.md) |

Read the [verb reference](../../plugin/blender-agent/docs/OPERATOR-VERBS.md) and
[development guide](../../docs/guides/tool-development.md). Use the current task's authority,
inputs, budget and holds. Existing authorization applies within its stated scope; ask only for
missing authorization or materially changed scope. Never infer permission to spend credits,
restart services or delete unrelated data from a request to diagnose a tool.

Report the tested entrypoint, revision, fixture and saved result. Distinguish capability tests
from real-asset acceptance and deployment. End with Status, Done, Verified and Open.
