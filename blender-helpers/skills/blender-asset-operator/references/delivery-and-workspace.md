# Workspace and asset delivery

Load before a large job, an optimized/exported derivative or Library filing. Use the current verb/API contract; limits and drive readings change.

## Workspace before the first step

- Estimate writes from source size, expected checkpoint count, render/map output and export copies. Obtain fresh free-space facts through permitted inspection or the owner, not a historical note.
- Give the developer the new job name before its folder exists if a different work drive is needed. The developer/storage owner arranges the workspace; the operator verifies the first checkpoint path through supported operations. Do not issue undocumented junction or service commands.
- Check every destination. Moving a job workspace does not automatically move its snapshot, cache or upload destinations. A pending cold archive need not block a job whose active workspace is ready.
- Distinguish copied, hash-verified, restorable and source-space-reclaimed. Never infer that an archive request freed disk. Preserve originals under the actual move/retention authorization.

## Master, derivative and exported file

Keep the accepted editable master separate from optimized PC/mobile deliveries and lighting-map sets. Before optimization, identify independently movable/controllable assemblies, materials and IDs that must survive. Shared meshes in a GLB do not guarantee GPU instancing or fewer draw calls.

Inspect the exported GLB, not just the authoring scene or a thumbnail:

| Risk | Relevant check |
|---|---|
| Wrong active scene or stale trial children | Export membership/counts; render the intended scene |
| Reparenting/batching changes position | Full world transforms and bounds, including rotated roots |
| Shading seams, lost alpha/materials | Re-import and open the same close/context views |
| Missing controls | Names, hierarchy, per-ID materials/lights and requested clips |
| Broken portability | Embedded versus external texture/dependency checks |
| Claimed optimization | File size, geometry and draw/batch evidence; device performance belongs to runtime testing |

Select checks proportional to the change. Do not rerun unrelated suites after passing relevant checks. A successful export report and a visible regression must be reconciled before acceptance.

## File the model and editable source

1. Copy the intended model ID from the actual result and verify its Library record before attaching source. A UUID-shaped typo can point elsewhere.
2. Publish the matching editable source, with source linkage, origin room, meaningful label and the intended collection/durable state where supported. Read back the records; report unsupported/pending filing explicitly. `post` makes shared snapshots; `publish` files assets. Neither proves durable promotion by itself.
3. For an upload-size refusal, use the documented size/dry-run route. `source_slim` was supplied for lossless packed-PNG recompression; confirm its current effects and output size. Do not silently downsample assets or delete originals to fit a cap.
4. Put review snapshots/reports in `rooms/<room-id>/<job>/`. Keep final assets and long-term references in the Library. Use `agent-share` for transfer details.
5. State what was verified: record hash, local export bytes, downloaded bytes, original checkpoint or re-saved copy. A `job_copy` save can change source bytes without changing the model. Pin exact handoff bytes; even a final newline changes a manifest hash.

Handoff: source/result IDs and checkpoints; file names/bytes/hashes when relevant; inspected views; export/filing checks; attempts and capability requests; known defects/approximations; explicit holds and next owner. Keep project-specific IDs in the project record, not this skill.
